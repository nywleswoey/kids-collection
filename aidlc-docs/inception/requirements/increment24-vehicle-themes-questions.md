### The seed CLI as it stands

- `loadSeed` `[loader.ts:8-12]` is pure, synchronous and network-free: `readFileSync` → `JSON.parse` →
  `seedFileSchema.parse`. Confirmed as the fail-fast gate.
- `seed-schema.ts` `[1-24]` enforces types, non-empty strings, the rarity enum and `sourceUrl` being
  URL-*shaped* only. **No** count, pyramid, uniqueness or length rule. Confirms **F2**.
- The review key is `slug(\`${theme.name}-${card.name}\`)` `[index.ts:165]`, and `--sync` calls
  `generateImage` again at the same line rather than reading `seed/review/`. Confirms **F1** — the
  reviewed bytes are not the published bytes.
- `generateImage` `[image.ts:40]` builds the Pollinations URL with **no `seed` parameter**, so the
  endpoint is non-deterministic. Confirms **F1**'s mechanism.
- `previewPrune` runs before any write and aborts without `--allow-prune` `[index.ts:102-120]`. A purely
  additive seed yields an empty radius, so `--sync` needs no flag and prompts nothing. Confirms **F3**.
- `.github/workflows/` holds `backup.yml` only — no test/lint CI. Confirms **F4**; parent **OQ-T-2**
  stays open.
- `--allow-prune` `[index.ts:105]` + `confirmDestructive` `[guard.ts:58-89]` are the existing
  `--allow-*` idiom the new guard must match: printed blast radius, non-zero exit by default, an
  explicit named flag, and no bypass channel other than a TTY.

### ⚠️ Finding A — `--review` regenerates the whole pool, not the new cards

`const exists = mode !== "review" && (await cardExists(...))` `[index.ts:140-141]`, and the theme loop
uses `themeId = mode === "review" ? "(review)" : await upsertTheme(...)` `[index.ts:135-136]`. Review
mode is deliberately **DB-free**, so it has no idea which cards already exist and generates an image for
**every card in the seed file**.

At 12 themes that is **360 images**, not 30. The global throttle hands out one request slot every
`SEED_THROTTLE_MS` (default 3000) `[index.ts:51, 236-242]`, so a full review run costs **≥18 minutes of
throttle alone**, plus 360 anonymous-tier Pollinations calls with their 429 exposure.

Both feature documents assume a review sitting is 30 images (vision Q7b-ii, technical T7a-ii). Neither
addresses this. **Resolved at Q2 = A.**

### ⚠️ Finding B — the review-file guard and the review pass must agree by construction

The feature's technical-environment.md scopes `--allow-unreviewed` to *"the cards it is about to
**insert**"*. For that count to ever be zero after an honest review sitting, `--review` must generate
exactly the same set. Q2 = A makes both sets "cards not present in the DB", computed the same way, so
the guard cannot disagree with the pass that satisfies it.

### Finding C — `seed/review/` holds 33 stale files

Untracked (`.gitignore` line `/seed/review/`), machine-local, named under the **old** `slug(theme-card)`
scheme, and a partial remnant of an earlier run. Under content-addressed naming they can never match a
hash, so they are inert — but they are also not a review record of anything. No action required; noted
so they are not mistaken for coverage.

### ⚠️ Finding D — `--publish` inserts too, and the vision's invariant is unqualified

The feature's technical-environment.md names `--sync` when specifying the unreviewed-publish guard, but
`--publish` also reaches `insertCardIfNew` `[index.ts:174]`. The vision's *"No unreviewed content path
to a child, ever"* is written without a mode qualifier. **FR9 therefore applies the guard to every
insert path, not only `--sync`.** This is a strengthening of the documents' intent, not a change of
scope — flagged here because it is a decision taken at Requirements stage and should be confirmed at
this gate.

## 3. Questions and answers

### Q1 — OQ-VT-J1: pyramid protected by a schema, not a PBT

The parent environment (Testing → Coverage Targets) states *"Every invariant that protects the
children's data must be covered by a property-based test or a contract test"*, and PBT is listed as
**blocking**. The 15/8/5/2 pyramid is named in the feature's "What Must NOT Change", and breaking it
makes a (theme, rarity) set-completion reward permanently unreachable — a child loses a bonus card they
would otherwise earn. T2 declined the PBT (option d) because `loadSeed` runs the schema on every seed
command and fails fast.

- (A) Write the PBT — a fast-check property over generated seed files
- (B) Declare the fail-fast schema a satisfying mechanism and write a carve-out into the parent
  `technical-environment.md`
- (C) Both
- (D) Leave OQ-VT-J1 open

**[Answer]: A** — write the PBT. Closes the question without adjudicating the principle, keeps the
parent's blocking constraint literally true, and is the cheaper of the two (a ~30-line test versus an
edit to a document this feature was explicitly told not to rewrite). Note the parent's own reasoning
cuts the same way given **F4**: with no test CI, a PBT and a schema are *both* only as good as the
person running them — except the schema also runs on every seed command, so having both is strictly
stronger than either.

### Q2 — Finding A: what should `--review` generate?

- (A) DB-aware **and** hash-resumable: generate only cards that would be inserted, and skip any card
  whose content-addressed review file already exists
- (B) Hash-skip only, stay offline
- (C) Add a `--theme "<name>"` filter
- (D) Leave as-is (360 images per run)

**[Answer]: A**. Consequence accepted: `--review` stops being DB-free and requires `DATABASE_URL`
(read-only usage: `cardExists` only, no write). In exchange the review set equals the insert set by
construction (Finding B), and a run interrupted by 429s resumes instead of restarting. (C) was declined
on the project's own stated grounds — *"policy is unenforceable; a mechanism makes it real"*.

### Q3 — Scope of `pnpm seed --check-urls`

- (A) Every card in the seed file
- (B) New/unpublished cards only
- (C) Every card, plus an optional `--theme` filter

**[Answer]: A** — all cards in the file. Keeps the flag network-only with no DB dependency, and
re-checks the existing 300 whose URLs have had the longest time to rot. Bounded concurrency, non-zero
exit listing every non-200.
